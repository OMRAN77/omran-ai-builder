والسبب الأقوى ليس الأرقام:

## ٢. التشخيص: ما وجدته فعليًا

### ⚠️ العيب الهيكلي #١ — الملف المنشور مصنوع يدويًا

- `js/app.bundle.js` = **١٧٫١٢٦ سطر / ١٫٠ ميغابايت**، وهو **دمج حرفي** لملفات `app-01` … `app-14` (تحققت: متطابقان بايت ببايت).
- **لا يوجد أي script بناء في المستودع.** الدمج يدوي.
- سجل Git يُثبت الانفصال: ملفات الأجزاء تغيّرت ~٢٨ مرة في السنة، بينما `app.bundle.js` أُعيد توليده **٦ مرات فقط**.
- النتيجة: ٣٨٪ من كودك المتعقَّب هو **نسخة مكرّرة من نفسه**، وأي نسيان لخطوة الدمج = تعديل تكتبه ولا يصل للمستخدم أبدًا. هذه بذاتها تُنتج فئة كاملة من "أخطاء لا تتكرر عندي".

### ⚠️ العيب الهيكلي #٢ — رقم إبطال الذاكرة متأخّر ٧ إصدارات

```
index.html →  app.bundle.js?v=388        ← متأخّر
sw.js      →  CACHE_NAME = '...-v395'    ← محدَّث
HEAD       →  v395
```
المستخدم العائد قد يُخدَم بحزمة قديمة. وأسوأ: `index.html` يُخزَّن في الـSW بسياسة network-first لكن الحزمة القديمة قد تبقى، فتحصل على **HTML جديد + JS قديم** = أخطاء `undefined is not a function` عشوائية لا تُفسّر.

### ⚠️ العيب الهيكلي #٣ — الأخطاء مكتومة عمدًا

| الموقع | كتل `catch(e){}` فارغة |
|--------|----------------------|
| `js/app-*.js` | **١٧٥** |
| `api/` | ٢٥ |
| `index.html` | ١٥ |
| **المجموع** | **١٩٩** |

مع **١٢٥ موضع `JSON.parse`** (كثير منها على مخرجات موديلات أو على SSE streams). كل فشل تحليل يختفي بصمت ويتحوّل إلى "الميزة ما اشتغلت" بلا أثر.

### ⚠️ العيب الهيكلي #٤ — `index.html` هو أخطر ملف عندك

- ٣٫٤٩٢ سطر / ٣٢٥ كيلوبايت في ملف واحد
- **٦٤ كيلوبايت CSS داخلي** (٥ كتل) + **٦٦ كيلوبايت JS داخلي** (٧ كتل)
- ٣٤ معالج `onclick=` داخلي يعتمد على **٧٧ دالة عامة على `window`**
- ٦٥٦ عنصر بـ`id`، ومنها **`id` مكرّر: `eduErrBack` مرتين** ← `getElementById` يُرجع الأول دائمًا، والثاني ميت
- **أعلى ملف تغييرًا في المستودع: ٣٣ تعديلًا** — أعلى تردد تغيير = أعلى كثافة عطب

### ⚠️ العيب الهيكلي #٥ — ٤٤ متغيّر بيئة بلا أي تحقّق

صفر تحقّق عند الإقلاع. ووجدت خللًا حقيقيًا في التسمية:
```js
api/_lib/memory.js:57   process.env.GROQ_API_KEY_    ← شرطة سفلية زائدة، دائمًا undefined
api/_lib/health.js:33   process.env.GROQ_API_KEY_1   ← اسم مختلف
```
أحدهما خاطئ بالضرورة، وفحص الصحة يكذب عليك.

### 🔴 مشكلة أمنية — سرّ ثابت في الكود

```js

const MONITOR_KEY = process.env.MONITOR_KEY || 'omran-monitor-2026';
```

## ٣. الخطة التنفيذية

### 🔥 المرحلة ٠ — أطفئ العمى (٤٨ ساعة، أعلى مردود في كل الخطة)

| # | الإجراء | الملف | الأثر |
|---|--------|-------|------|
| 1 | احذف السرّ الاحتياطي الثابت | `api/_lib/client-errors.js` | 🔴 أمني |
| 2 | أضف `scripts/build.mjs` يُنشئ الحزمة + يبصم الاسم تلقائيًا | جديد | يقتل عيب #١ و#٢ نهائيًا |
| 3 | وحّد الترقيم: بصمة محتوى واحدة تُستخدم في `index.html` و`sw.js` | `index.html`, `sw.js` | يقتل "أخطاء لا تتكرر" |
| 4 | أنشئ `.gitignore` وأخرج `source-code.zip` و`videos_tmp/` | جديد | −٨ م.ب فورًا |
| 5 | صحّح `GROQ_API_KEY_` → `GROQ_API_KEY_1` | `memory.js:57` | خلل مؤكَّد |
| 6 | أصلح الـ`id` المكرّر `eduErrBack` | `index.html` | خلل مؤكَّد |
| 7 | **اسحب سجل الأخطاء الحقيقي** من `/api/client-errors?key=…` وصنّفه | — | يحوّل الخطة من تقديرية إلى مؤكَّدة |

سكربت البناء (يحلّ العيبين #١ و#٢ في ٢٥ سطرًا):
```js
// scripts/build.mjs   →  node scripts/build.mjs
import { readFile, writeFile, readdir } from 'node:fs/promises';
import { createHash } from 'node:crypto';

const dir = 'js';
const parts = (await readdir(dir)).filter(f => /^app-\d\d-.*\.js$/.test(f)).sort();
if (parts.length !== 14) throw new Error(`توقعت ١٤ جزءًا، وجدت ${parts.length}`);

const bundle = (await Promise.all(parts.map(p => readFile(`${dir}/${p}`, 'utf8')))).join('\n');
const hash = createHash('sha256').update(bundle).digest('hex').slice(0, 8);

await writeFile(`${dir}/app.bundle.js`, bundle);

// بصمة واحدة، مصدر حقيقة واحد — لا ترقيم يدوي بعد اليوم
let html = await readFile('index.html', 'utf8');
html = html.replace(/app\.bundle\.js\?v=[^"]*/g, `app.bundle.js?v=${hash}`);
await writeFile('index.html', html);

let sw = await readFile('sw.js', 'utf8');
sw = sw.replace(/CACHE_NAME = '[^']*'/, `CACHE_NAME = 'omran-ai-builder-${hash}'`);
await writeFile('sw.js', sw);

console.log(`✓ الحزمة: ${parts.length} جزءًا، ${bundle.split('\n').length} سطرًا، بصمة ${hash}`);
```
وفي `package.json`:
```json
"scripts": {
  "build": "node scripts/build.mjs",
  "verify": "node scripts/build.mjs && git diff --exit-code js/app.bundle.js index.html sw.js",
  "check": "for f in js/app-*.js api/*.js api/_lib/*.js; do node --check $f || exit 1; done"
}
```
`npm run verify` يفشل إذا نسيتَ إعادة البناء. **هذا وحده يمنع أشهرًا من الأخطاء الوهمية.**

### 🛡️ المرحلة ١ — شبكة الأمان (٣ أيام)

1. **`.github/workflows/ci.yml`** على كل push و PR: `npm run check` → `npm run verify` → اختبارات الدخان. مع Branch protection: لا دمج على الأحمر.
2. **`api/_lib/env.js`**: تحقّق واحد من الـ٤٤ متغيّرًا — إلزامي مقابل اختياري، وفشل بصوت عالٍ برسالة صريحة عند الإقلاع.
3. **حظر الكتم الصامت**: قاعدة ESLint `no-empty` (`allowEmptyCatch: false`)، وطبّقها بالتدرّج بدءًا بأخطر ٣ ملفات. لكل `catch` إمّا تسجيل أو تعليق صريح يشرح لماذا الصمت مقصود.
4. **حوّل ١٩٩ كتمة إلى إشارات**: أضف `logError(scope, e)` واحدة تُبلّغ `/api/client-errors` الموجود عندك أصلًا.
5. **٥ اختبارات دخان Playwright** فقط: تحميل الصفحة بلا خطأ console → تسجيل الدخول → نداء AI واحد → الدفع (وضع اختبار) → تحميل الـSW.
6. **Preview لكل PR** على Vercel — أنت أصلًا مربوط بـVercel، فعِّلها فقط.

**🚦 بوابة قرار ①: لا تتقدّم قبل أن يصبح CI أخضر ومستقرًا.**

### 🩹 المرحلة ٢ — إيقاف النزيف (أسبوع)

1. رتّب سجل `/api/client-errors` الحقيقي بالتكرار، وأصلح **أعلى ١٠ فقط** — إصلاحًا مباشرًا بلا إعادة هيكلة.
2. **حصّن الـ١٢٥ موضع `JSON.parse`**: دالة واحدة `safeParse(text, fallback, scope)` تُسجّل الفشل ولا تكتمه. ابدأ بـ`api/_lib/agent.js` (تحليل SSE — الأكثر هشاشة).
3. **طبقة واحدة لسلوك الشبكة**: مهلة + إعادة محاولة مع backoff + `AbortSignal` + رسالة مستخدم مفهومة. المزوّدون التسعة يمرّون عبرها.
4. **تحقّق من مخرجات الموديل بمخطط** قبل استخدامها، لا `JSON.parse` عارٍ على ردّ نموذج.
5. **تحقّق من `maxDuration: 300`** في `vercel.json`: هذه تحتاج خطة Pro. على Hobby الحد ٦٠ ثانية → عمليات الفيديو تُقطع بصمت. تحقّق من خطتك واضبط الرقم على الحقيقة.
6. **لكل خطأ تُصلحه: اختبار انحدار.** لا استثناء.

**🚦 بوابة قرار ②:** انخفض معدل الأخطاء ≥ ٥٠٪؟
- **نعم** → المرحلة ٣.
- **لا** → لا تُعمّم الفشل على المشروع؛ اعزل الوحدة المسؤولة وأعد بناءها وحدها.

### 🧩 المرحلة ٣ — فك التشابك (٤ أسابيع)

**هنا فقط تُستخدم إعادة البناء — وعلى ملف واحد: `index.html`.**

هذا الملف (٣٫٤٩٢ سطرًا، ٦٤ ك.ب CSS + ٦٦ ك.ب JS داخلي، ٣٣ تعديلًا) هو المكان الوحيد الذي فيه الترميم أغلى من البناء:

1. استخرج ٦٤ ك.ب من الـCSS إلى `css/` مقسّمًا حسب الميزة، وأزل الـ٥٢ `!important`.
2. استخرج ٦٦ ك.ب من الـJS الداخلي إلى `js/app-15-*.js` ليمرّ بسكربت البناء.
3. أزل الـ٣٤ `onclick=` واستبدلها بـ`data-action` + مُوجِّه أحداث واحد → ينهي الاعتماد على ٧٧ متغيّرًا عامًا.
4. اقسم `index.html` إلى قوالب جزئية تُدمج وقت البناء.

ثم على الجانب الخفي:
```
js/
  core/        منطق نقي: حالة، تحقّق، أدوات — صفر DOM
  ui/          عرض فقط
  services/    نداءات api/ عبر طبقة الشبكة الموحّدة
api/
  _lib/        كما هي — سليمة، لا تُمسّ
  _lib/env.js  جديد: تحقّق البيئة
```
**قواعد غير قابلة للتفاوض:**
- PR واحد ≤ ٤٠٠ سطر، موضوع واحد
- ممنوع خلط تغيير سلوك مع تنظيف في نفس الـPR
- اختبار **قبل** النقل، ثم النقل، ثم حذف القديم — ثلاثة PRs
- كل PR يمرّ عبر `npm run build` — لا تعديل يدوي للحزمة بعد اليوم

**ترتيب التنفيذ** (من الأقل خطرًا إلى الأعلى قيمة):
`env` → `logError` → `safeParse` → طبقة الشبكة → استخراج CSS → استخراج JS الداخلي → مُوجِّه الأحداث → `app-13-stocks-init` (١١ تعديلًا) → `app-06-checkout` (٧ تعديلات، ماسّ بالمال — الأخير وبأعلى تغطية).

## ٦. ما **لا** تفعله

- ❌ **لا تُعِد البناء من الصفر** — سترمي ٧٥ وحدة `_lib` سليمة، و٩ تكاملات مزوّدين، ونظام دفع يعمل، وبنية رصد أخطاء جاهزة… لتصلح مشكلات يحلّها سكربت من ٢٥ سطرًا.
- ❌ **لا تُحوّل إلى React/Next الآن** — تكلفة هائلة، وصفر من أخطائك الحالية سببها غياب فريمورك.
- ❌ **لا تعدّل `app.bundle.js` يدويًا مرة أخرى**، أبدًا.
- ❌ **لا تضف ميزة واحدة** قبل انتهاء المرحلة ٢.
- ❌ **لا تُصلح ١٩٩ كتمة في PR واحد** — أضف الأداة أولًا، ثم انقل بالتدرّج.
