# دليل النشر — omran-ai-builder

## الحقيقة الأساسية
المشروع **غير مربوط بـ GitHub** (`link: none`). النشر يتم بأمر مباشر.
مستودع GitHub **متأخّر ~96KB** عن الإنتاج → **لا تنشر من GitHub أبدًا**.

## الطريقة الآمنة (استُخدمت بنجاح ٥ أغسطس ٢٠٢٦)
1. اقرأ آخر نشر إنتاجي: `GET /v9/projects/{PRJ}?teamId=` → `targets.production.id`
2. اسحب شجرة المصدر: `GET /v6/deployments/{id}/files` → عقدة `src` فقط (تجاهل `out`)
3. لكل ملف: `GET /v7/deployments/{id}/files/{uid}` → `{data: base64}`
   **تحقّق: sha1(البايتات) == uid** ← ضمان النسخ الحرفي
4. ارفع الملف المعدَّل فقط: `POST /v2/files` + رأس `x-vercel-digest: <sha1>`
5. أنشئ النشر: `POST /v13/deployments?skipAutoDetectionConfirmation=1`
   `{name, project, target:"production", files:[{file, sha, size}...]}`
   الملفات غير المعدَّلة تُمرَّر ببصمتها فقط → لا يتغيّر فيها بايت واحد
6. تابع `GET /v13/deployments/{id}` حتى `READY` (عادة ١٠ ثوانٍ)

## التحقّق بعد النشر (إلزامي)
- المنشور == الملف المحلي (`cmp`)
- `sw.js` و `app.bundle.js`: بصمة مطابقة للأصل
- نقاط API: قارن رمز الاستجابة بين النشر القديم والجديد (يجب أن تتطابق)
  ملاحظة: النقاط الحقيقية ٨ دوالّ (`api/ai.js` …) + ٦٦ تحويلة في `vercel.json`.
  `GET` عليها يعيد **405** — هذا سليم، ليس خطأ.

- `/js/app.bundle.js`   ← داخل `/js/`، وليس الجذر

تحذير: مسار خاطئ يعيد صفحة 404 ببصمة **متغيّرة كل طلب** (رقم طلب فريد) — تبدو كأنّ الملف تغيّر. استخرج المسار من `grep -o 'src="[^"]*"' live.html` بدل التخمين.

## معاينة أوّلًا (منذ ٦ أغسطس ٢٠٢٦)

كل دفعة تمرّ بأربع خطوات لا ثلاث:

1. `bun scripts/deploy-files.ts preview "<وصف>" <ملفات>`
2. `MONITOR_KEY=… node scripts/smoke.mjs <رابط المعاينة>` — يجب ١٨/٠
3. `bun scripts/deploy-files.ts production "<وصف>" <ملفات>` (البصمات نفسها
   فلا رفع جديد)
4. `node scripts/smoke.mjs` على الإنتاج + `bun scripts/gh-push.ts "<رسالة>" <ملفات>`

`scripts/gh-push.ts` عامّ: يأخذ الرسالة والمسارات من `/tmp/vc/src` ويتحقّق
بالبصمة بعد الدفع. التنزيل للتحقّق يجب أن يكون داخل `/tasklet` — أدوات
الاتصال لا ترى `/tmp` المحلّي.

## بوّابة ① داخل خطّ النشر (٦ أغسطس ٢٠٢٦)

النشر في هذا المستودع يمضي من `scripts/deploy-*.ts` إلى Vercel API مباشرةً،
**ولا يعبر GitHub**. فـGitHub Actions لا يحرس هذا الطريق ولو كان أخضر. الحارس
نُقل إلى حيث يمرّ النشر فعلًا:

1. **قبل أوّل اتّصال بـVercel:** `npm run ci` (check · guard · verify · test).
   أحمر ⇒ خروج ١ ولا يُلمس Vercel. لا مفتاح تجاوز — إن احتجتَ تجاوزًا فقلها بصوتٍ عالٍ.
2. **بعد `READY`:** `node scripts/smoke.mjs <url>` على النشرة نفسها.
   أحمر على المعاينة ⇒ لا ترقية. أحمر على الإنتاج ⇒ يُطبع أمر الرجوع.
3. **`LAST-DEPLOY.txt`** يسجّل `smoke=green|red|skipped`.
4. **الترتيب المعتمد:** معاينة → دخان → ترقية → دخان.

مُتحقَّق في الاتّجاهين: ملفّ فيه خطأ تركيبيّ أوقف النشر قبل Vercel،
والمسار الأخضر أنشأ `dpl_5BTaWkRKzb5p96iGLBFhAEUDonir` ودخانه ١٨/٠.

## قاعدة أُضيفت بعد حادثة ٦ أغسطس: لا عملٌ يعيش في الصندوق وحده

**ما جرى:** رقعة «قفل t» (٥ أسطر، مثبَّتة خضراء على المعاينة) كانت موجودة في
`/tmp/vc/src` فقط — لم تُدفع إلى GitHub لأنّ سقف اليوم منع دفعة ثالثة. أُعيد
تشغيل الصندوق فزال `/tmp/vc` بكامله. لم يضع شيء لأنّي استخرجتُ الرقعة من
**الحزمة الحيّة للمعاينة** مقيسةً على الإنتاج — لكنّ ذلك كان حظًّا، لا نظامًا.

**القاعدة:** كلّ رقعة تُنشر على المعاينة ولا تُرقَّى في اليوم نفسه **تُحفظ فورًا**
في `/tasklet/agent/home/patches/<batch>/` مع: المقطع، مرساة الإدراج، معرّف نشر
المعاينة، وعدد الأسطر **المقيس** (`diff` لا تقدير). قبل إنهاء أيّ يوم:
`ls patches/` يجب أن يطابق كلّ معاينة غير مُرقّاة.

**استرجاع رقعة من نشرٍ حيّ (حين يزول الصندوق):**
```sh
curl -sf "$PREVIEW_URL/js/app.bundle.js" -o /tmp/prev.js
curl -sf "$PROD_URL/js/app.bundle.js"    -o /tmp/prod.js
diff -u /tmp/prod.js /tmp/prev.js        # الرقعة الحقيقيّة، مقيسة
```
ملاحظة: `js/app-NN-*.js` تعيد **٤٠٤** في النشر (الحزمة وحدها تُخدَم) — استخرج من الحزمة.
