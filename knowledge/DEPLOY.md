مرجع أعلى: `/tasklet/workspace/home/AGENTS.md` · المشروع: `PROJECT.md` · الفخاخ: `PITFALLS.md` · الحالة: `STATE.md`.
مصدر تفصيليّ أصليّ: `/tasklet/agent/home/deploy/RUNBOOK.md` — هذا الملف تلخيصه التنفيذيّ.

## ١. الحقيقة الأساسيّة التي تحكم كل شيء
مشروع Vercel **غير مربوط بـ GitHub** (`link: none`). النشر يتم بأمر مباشر إلى Vercel API.
**دفع GitHub والنشر على Vercel فعلان منفصلان تمامًا** — لا تفترض أن دفع GitHub ينشر،
ولا أن النشر يحدّث GitHub. كلاهما يجب أن يُنفَّذ صريحًا وبالترتيب أدناه.
مستودع GitHub تاريخيًّا كان متأخّرًا عن الإنتاج بنحو ٩٦ ك.ب — **لا تنشر أبدًا انطلاقًا من GitHub**؛
انطلق دائمًا من نشرة الإنتاج الحيّة على Vercel كمصدر حقيقة.

## ٢. أين المفاتيح
- `/tasklet/agent/home/.secrets/vercel.env` — مفتاح Vercel API. صلاحيّة `600`.
- `/tasklet/agent/home/.secrets/monitor.env` — `MONITOR_KEY` لقراءة/تنظيف سجل الأخطاء.
- **لا يُطبَع محتوى هذين الملفّين، ولا يُدفَع، ولا يُذكَر نصّه في أي تقرير أو commit.**
  يُشار إليهما بالمسار فقط.
- `AUTH_SECRET` **مشفَّر في Vercel** — لا يمكن توليد JWT حقيقيّ محليًّا لأي اختبار e2e
  يحتاج جلسة مصادقة على الإنتاج. أي اختبار من هذا النوع يبقى يدويًّا عبر متصفّح حقيقيّ.

## ٣. السكربتات (كلّها في `/tasklet/agent/home/scripts/` إلا ما ذُكر غيره)
| السكربت | الوظيفة |
|---|---|
| `pull-src.ts` | يسحب شجرة `src` من آخر نشرة إنتاجيّة عبر `GET /v6/deployments/{id}/files` (يتجاهل `out`)، ويتحقّق أن `sha1(البايتات) == uid` لكل ملف — ضمان نسخ حرفي. |
| `deploy-files.ts` | يرفع الملفّات المعدَّلة فقط (`POST /v2/files` + رأس `x-vercel-digest`) وينشئ نشرة (`POST /v13/deployments`) على هدف `preview` أو `production`. الملفّات غير المعدَّلة تُمرَّر ببصمتها فقط دون تغيير بايت واحد فيها. |
| `deploy-index.ts` | نفس آليّة `deploy-files.ts` مخصَّصة لدفعات تلمس `index.html` فقط. |
| `vercel-rollback.ts` | يُعيد نشرة سابقة معروفة إلى `production` بمعرّف `dpl_...`. |
| `gh-push.ts` | عامّ: يأخذ رسالة الالتزام والمسارات من `/tmp/vc/src`، يدفع إلى `main`، ثم **يتحقّق بالبصمة بعد الدفع** (لا يثق بقراءة فوريّة لملفّ محليّ — انظر الدرس أدناه). |
| `gh-push-one.ts` | نسخة مبسّطة من `gh-push.ts` لملفّ واحد. |
| `gh-snapshot.ts` | يأخذ لقطة كاملة من شجرة `main` الحاليّة قبل أي دفعة كبيرة. |
| `p3-probe-any.ts` | مسبار DOM عامّ (عدد العناصر، مفاتيح وظيفيّة، بصمات) يقارن نشرتين — الأداة الأساسيّة للتحقّق الحيّ في المرحلة ٣ وما بعدها. |
| `kv-purge-agent-errors.ts` | تنظيف انتقائيّ لسجل KV من أثر جلسات الوكيل نفسه (تجربة جافّة افتراضيًّا — انظر `PITFALLS.md`). |
| `smoke.mjs` | اختبار دخان (يحتاج `MONITOR_KEY`) — يُشغَّل على كل نشرة قبل الترقية وبعدها. |
| `build.mjs` / `npm run bundle` | يجمع `js/app-NN-*.js` إلى `app.bundle.js`، يبصم المحتوى (hash)، ويحدّث `?v=` في `index.html` و`CACHE_NAME` في `sw.js` بالبصمة نفسها — **مصدر حقيقة واحد**. لا تحرير يدويّ لـ`app.bundle.js` أبدًا. |

## ٤. الترتيب المعتمد — أربع خطوات لا ثلاث (منذ ٦ أغسطس ٢٠٢٦)
1. **معاينة:** `bun scripts/deploy-files.ts preview "<وصف>" <ملفات>`
2. **دخان على المعاينة:** `MONITOR_KEY=… node scripts/smoke.mjs <رابط المعاينة>` — يجب **١٨/٠**.
   أحمر على المعاينة ⇒ **لا ترقية**، عالج ثم أعد المعاينة.
3. **ترقية للإنتاج:** `bun scripts/deploy-files.ts production "<وصف>" <ملفات>`
   (البصمات نفسها من خطوة ١ ⇒ لا رفع جديد، النشر فقط يُعاد تثبيته على `production`).
4. **دخان على الإنتاج + دفع GitHub:** `node scripts/smoke.mjs` على رابط الإنتاج،
   ثم `bun scripts/gh-push.ts "<رسالة>" <ملفات>`. أحمر على الإنتاج ⇒ **يُطبَع أمر الرجوع فورًا**.

### بوّابة قبل أول اتصال بـVercel
`npm run ci` (يشمل `check` · `guard` · `verify` · `test`). أحمر ⇒ خروج بكود ١، **لا يُلمَس Vercel إطلاقًا**.
لا مفتاح تجاوز لهذه البوّابة — إن احتاج الوكيل تجاوزها فعليه قوله بصوت عالٍ لعمران، لا تجاوزها صمتًا.
`LAST-DEPLOY.txt` يسجّل `smoke=green|red|skipped` لكل نشرة.

**سبب هذا الترتيب:** خطّ النشر يذهب من `scripts/deploy-*.ts` إلى Vercel API مباشرة **ولا يعبر GitHub
أبدًا** — فـGitHub Actions (CI) لا يحرس هذا الطريق ولو كان أخضر بالكامل. لذلك انتقلت البوّابة
إلى داخل خطّ النشر نفسه (`npm run ci` قبل الاتصال، `smoke.mjs` بعده) لا إلى GitHub وحده.
CI في `/tasklet/agent/home/ci/ci.yml` **معطَّل حاليًّا** — بانتظار نطاق `workflow` من GitHub
(المستخدَم لا يملك الصلاحية لتفعيل الـworkflow تلقائيًّا؛ يحتاج إذنًا/توكن بنطاق أوسع).

## ٥. التحقّق بعد النشر (إلزاميّ، لا اختياريّ)
- المنشور == الملف المحليّ (`cmp` بايت-ببايت).
- `sw.js` و `js/app.bundle.js`: بصمة (hash) مطابقة للبناء المصدَّق.
- نقاط API: قارن رمز الاستجابة بين النشرة القديمة والجديدة (يجب أن تتطابق).
  ٨ دوالّ فعليّة + ٦٦ تحويلة في `vercel.json`. `GET` عليها يعيد **405** — هذا **سليم**، ليس خطأ.
- مسارات التحقّق الصحيحة (لا تُخمَّن):
  - `/templates-data.js` ← في الجذر، **وليس** في `/js/`.
  - `/js/app.bundle.js` ← داخل `/js/`، **وليس** في الجذر.
  - `/sw.js` ← في الجذر.
  - **تحذير:** مسار خاطئ يعيد ٤٠٤ ببصمة **متغيّرة كل طلب** (رقم طلب فريد) — يبدو كأن الملف
    تغيّر فعلًا وهو ليس كذلك. استخرج المسار الحقيقيّ من `grep -o 'src="[^"]*"' live.html`،
    لا بالتخمين.
- ١٨ مسار `js/app-NN-*.js` تعيد **٤٠٤** في الإنتاج (تُخدَم الحزمة وحدها) — هذا **سليم ومتوقَّع**،
  ليس عطبًا. راجع `PITFALLS.md`.
- مسبار DOM: قارن عدد العناصر بخطّ الأساس (انظر `PITFALLS.md` §"أساس عدد عناصر DOM").

## ٨. قاعدة النقل المُثبَت بلا كلفة (احتساب السقف)
النقل المُثبَت هويّة بايتاته بـ`sha256` (نقل حرفيّ، صفر تغيير منطق) **يُحتسَب صفر سطر** ضمن سقف
٤٠٠ سطر/يوم — لكن **بشرط**: إثبات هويّة البايتات + مسبار (`p3-probe-any.ts`) يطابق ترتيب DOM
والعناصر قبل/بعد. مثال: المرحلة ٣ كاملة (٧ شرائح، ١٦ ملفًّا، ٤٤٠٦ سطرًا أُعيد ترتيبها) = **٢٠ سطرًا
محتسَبًا فقط** (المنطق الجديد الصافي). كل سطر يُدفع فعليًّا إلى `main` — بما فيه أدوات ومسبارات
الوكيل نفسه — يُحتسَب ضمن السقف، بلا استثناء.

## ٩. لا عملٌ يعيش في الصندوق وحده (قاعدة ما بعد حادثة ٦ أغسطس)
كل رقعة تُنشر على معاينة ولا تُرقَّى إلى الإنتاج في نفس اليوم **تُحفظ فورًا** في
`/tasklet/agent/home/patches/<batch>/`: المقطع (diff)، مرساة الإدراج، معرّف نشرة المعاينة،
وعدد الأسطر **المقيس بـ`diff`** لا المقدَّر. `/tmp/` يُفرَّغ عند إعادة تشغيل الصندوق — لا تعتمد
عليه لأي شيء غير مُنشَر أو غير محفوظ في `/tasklet`. قبل إنهاء أي يوم: `ls patches/` يجب أن
يطابق كل معاينة غير مُرقّاة.

**استرجاع رقعة من نشرة حيّة إن زال الصندوق:**
```sh
curl -sf "$PREVIEW_URL/js/app.bundle.js" -o /tmp/prev.js
curl -sf "$PROD_URL/js/app.bundle.js"    -o /tmp/prod.js
diff -u /tmp/prod.js /tmp/prev.js   # الرقعة الحقيقيّة، مقيسة لا مقدَّرة
```
