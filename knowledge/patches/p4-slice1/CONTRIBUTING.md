# كيف يُلمَس هذا المستودع

مشروع واحد، صاحبه **عمران**، ووكيله يدفع إلى `main` مباشرةً. القواعد أدناه ليست
شكليّات: كلّ سطر منها مكتوب لأنّ خسارةً وقعت من قبل.

## بيئة واحدة، لا ثلاث
- Node **24** في كلّ مكان: `engines` في `package.json`، و`.nvmrc`، وVercel، وCI.
- `npm run ci` = `check` (تحقّق صياغة) + `guard` (حارس الأسرار) + `verify` (بصمة الحزمة) + `test`.
  لا نشر ولا دفع قبل أن يخضرّ.

## الحزمة تُبنى ولا تُحرَّر
`js/app.bundle.js` **مولَّدة**. عدّل `js/app-NN-*.js` ثمّ `npm run bundle` ثمّ `npm run verify`.
تحريرها بالید يُفقد كلّ إصلاح لاحق.

## سقف اليوم
- **٤٠٠ سطر منطق جديد في اليوم، طلب سحب واحد.**
- النقل الحرفيّ المُثبَت بـsha256 (نفس البايتات في مكان آخر) = **صفر سطر محتسَب**.
- التجاوز يُسجَّل صريحًا في `design/DECISIONS.md` — لا يُخفى.

## أربع خطوات لكلّ دفعة
1. **نسخة احتياطيّة** قبل اللمس (ملفّات الإنتاج + نسخة `main`).
2. **دفع** ثمّ التحقّق من **بصمة git blob** لكلّ ملفّ — لا من ملفّ محلّيّ نُزّل قبل لحظة
   (`/tasklet` متّسق بالتراخي ويكذب في الاتّجاهين).
3. **تحقّق بعد النشر**: دخان ١٨/١٨ + مسبار متصفّح يقارن العناصر والترتيب قبل/بعد.
4. **تقرير صادق**: ما نجح، وما لم يُقَس، وما بقي مجهولًا.

## أبواب مقفولة — لا تُفتح إلا بأمر مكتوب صريح
المال (`stripe`/`paypal`/الأرصدة/الشحن) · بيانات المستخدمين · حذف أيّ مستودع أو قاعدة ·
إنفاق المال · نشر أيّ مفتاح.

## خطوط حمراء ثابتة
- **الجوّال مُتجاهَل عمدًا** — كمبيوتر فقط، ولا يُلمس تخطيط الجوّال.
- `stockTickerToggle` لا يُحذف. **مها** تبقى في مكانها.
- «المحادثات» و«الملفّات» تبقى صامتتين على الكمبيوتر — قرار مُغلق.
- لا ميزة جديدة قبل انتهاء المرحلة ٢.
