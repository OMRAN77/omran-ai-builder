# سجلّ القرارات

## ١٦ سبتمبر ٢٠٢٦ — v-maha-firstword: أول جملة في مكالمة مها تضيع فتردّ من المرة الثانية
- **العرض:** عند فتح شاشة الصوت اللحظي (Realtime) يُقفل المايك الحيّ (`inputTrack.enabled=false`) ٢-٥ ثوانٍ حتى تجهز الجلسة، وأي كلام في تلك النافذة لا يُبثّ ولا يُخزّن — يعيده المستخدم فتردّ مها من المرة الثانية. زاد الوهم أنّ الحالة أثناء التجهيز كانت تعرض «أفكر...» فيظنّ أنها سمعته.
- **القرار:** نسخة (clone) مستقلّة من مسار الصوت (`mahaStartPreBuffer`) تبدأ التسجيل المحلّي قبل قفل المسار الحيّ مباشرة — `clone()` يجعل `enabled` مستقلًّا فلا يتأثر بإطفاء الأصل لاحقًا. تُخزَّن مقاطع PCM16 (بعد تصغير المعدّل لـ٢٤ك.هرتز) في مخزن دائريّ سقفه ٦ ثوانٍ. عند الجاهزية (`mahaFlushPreBuffer`, قبل فتح المسار الحيّ وقبل `mahaRtReady=true`): لو المخزن فيه كلام فعليّ (ذروة > عتبة صمت) يُبثّ بـ`input_audio_buffer.append` مجزّأً ثم `input_audio_buffer.commit` واحد، ثم يوقف المسجّل المؤقت ويُفرغه دائمًا (سواء أُرسل أو لا) — فلا ازدواج بث. فشل الالتقاط (متصفح لا يدعم) صامت آمن مع `console.warn` واحد، بلا استثناء. حالة «أفكر» استُبدلت بنص تجهيز صريح `⏳ لحظة، أجهّز الجلسة…` قبل الجاهزية، ونغمة استعداد قصيرة (`mahaPlayReadyBeep`, ≤١٢٠م.ث) عند «🟢 أستمع» تعيد استعمال `AudioContext` مؤشر المايك القائم بدل إنشاء واحد جديد.
- **الاختبار:** `tests/maha-firstword.test.cjs` يثبّت ترتيب العمليات نصيًّا (التسجيل قبل القفل، الإفراغ قبل الفتح الحيّ وقبل الجاهزية، النغمة بعدها)، وأن الإفراغ يتحقق من الكلام الفعلي قبل أي إرسال، وأن الفشل صامت، وأن لا AudioContext جديد للنغمة، وأن الحزمة أُعيد بناؤها. الدرس: `MediaStreamTrack.enabled=false` يُصمِت كل مستهلكي المسار الأصلي (حتى تحليل محلّي عبره) — أي التقاط أثناء نافذة الكتم يحتاج `clone()` مستقلًّا لا نفس المسار.

## ١٦ سبتمبر ٢٠٢٦ — v-owner-direct: «فيه أشياء أريدها يقول لا أستطيع مجاملة — لا أريد المجاملات ولا الكذب»
- **العرض:** المالك لا يريد الإضرار بأحد، لكنّه ينزعج من الرفض الزائد/المجاملة على طلبات مشروعة. أراد صراحة ومباشرة دائمة، بلا «لا أستطيع» غامضة ولا إطراء ولا كذب. (طلب أيضًا نموذج كودي الأرخص = Sonnet 5.)
- **القرار:** (أ) **v-owner-direct** — سطر دائم للمالك وحده يقتل المجاملة والرفض الزائد ويطلب الصراحة، ويترك أمان النموذج الأساسيّ (الضرر الحقيقيّ) كما هو. مضاف في مكانين: `api/ai.js` (مسار factory للمالك يأخذ `OWNER_DIRECT_NOTE` فقط لا طبقة التطبيق)، و`api/_lib/agent.js` (نصّ نظام الوكيل للمالك). (ب) **كودي على Sonnet 5**: النموذج الافتراضيّ لتفويض الكود (`omran-agent.yml` + وصف `agent-delegate.js`) من `claude-fable-5-1` (الأغلى) إلى `claude-sonnet-5` (رخيص وقويّ للكود). الوكيل أصلًا يملك صلاحيات Claude Code الكاملة عبر GitHub Actions (بلا Railway)، والنشر/الدمج يبقى بيد المالك/الجلسة.
- **الاختبار:** `tests/owner-raw.test.cjs` حُدّث (المالك يأخذ سطر الصراحة فقط لا طبقة كاملة، mistral وclaude)، و`tests/agent-context.test.cjs` (الافتراضيّ Sonnet 5)، و`npm run ci` يمرّ. الدرس: «بلا رفض إطلاقًا» مستحيل (أمان النموذج داخليّ)، لكن المجاملة والرفض الزائد طبقةٌ يمكن قتلها بسطر توجيه صريح للمالك.

## ١٥ سبتمبر ٢٠٢٦ — v-cc-cheap: «Claude Code خلّه الأرخص، والاثنين»
- **العرض:** Claude Code كان يفشل بـ401 (مصادقة — التوكن في Railway، خارج نطاق الكود)، والمالك أراد «الأرخص، والاثنين» (نموذجان أساسيّ + احتياطيّ). تصحيح جوهريّ: الإعداد كان **أغلى تركيبة ممكنة** — `claude-fable-5-1` أساسيّ + `claude-opus-5` احتياطيّ + جهد `max` (بعد شكوى «ضعيف» سابقًا). ومرجع الأسعار يثبت أنّ **Fable هو الأغلى ($10/$50) لا الأرخص** كما فُهم؛ الأرخص Haiku 4.5 ($1/$5)، وSonnet 5 ($2/$10) أفضل توازن للكود.
- **القرار:** `cc-bridge/server.mjs` — النموذجان: أساسيّ **Sonnet 5** (قويّ للكود ورخيص) واحتياطيّ **Haiku 4.5** (الأرخص). التطبيق لا يفرض نموذجًا (يرسل بلا `model`) فتغيير الجسر يكفي. الجهد بقي `max` (متروك للمالك خفضه لتوفير أكثر). المتغيّرات في Railway (`CC_MODEL`/`CC_FALLBACK_MODEL`) تتقدّم على هذه الافتراضات إن كانت مضبوطة — يلزم تركها فارغة أو ضبطها. الـ401 يبقى بيد المالك: تجديد `CLAUDE_CODE_OAUTH_TOKEN` عبر `claude setup-token` (لا تُلمس المفاتيح).
- **الاختبار:** `node -c cc-bridge/server.mjs` سليم، و`npm run ci` للتطبيق يمرّ (لا يشمل الجسر). الجسر يعيد نشره على Railway عند تغيّر `cc-bridge/**`. الدرس: «الأرخص» يتطلّب مرجع أسعار لا تخمينًا — أغلى نموذج (Fable) كان مُقدَّمًا على أنّه الأرخص.

## ١٥ سبتمبر ٢٠٢٦ — v-psheet-theme: «أنماط الصور — الخلفيّة بيضاء إذا الصفحة بيضاء وسوداء إذا سوداء»
- **العرض:** المالك بدّل الثيم إلى الفاتح على صفحة «أنماط الصور» فاختفى عنوان الرأس. إعادة الإنتاج بلقطة: جسم الصفحة `#portraitStyleSheet` مثبّت داكن (`background:#0b0b0d`) وعنوان الرأس بلا لون صريح فيرث `--text` — في الفاتح يصير النصّ داكنًا على خلفيّة داكنة فيختفي. **أوّل محاولة (v-psheet-darkfixed) ثبّتت الصفحة داكنة دائمًا؛ صحّح المالك: يريدها تتبع الثيم فعلًا — خلفيّة بيضاء في الفاتح وسوداء في الداكن.**
- **القرار:** جعل الصفحة تتبع الثيم لا تثبيتها. (أ) `js/partials-core.js`: حاوية `#portraitStyleSheet` تبقى `background:#0b0b0d` كافتراضٍ داكن، ولونها `var(--text)` (يتبع الثيم)؛ العدّاد `var(--muted)`. (ب) `css/modules.css` — قواعد الوضع الفاتح: `html[data-mode="light"] #portraitStyleSheet{background:var(--bg); color:var(--text)}` تقلب الجسم فاتحًا، مع تفتيح الشرائح (`.pstyleChip` خلفيّة `rgba(0,0,0,.05)` ونصّ `--text`) والتذييل (`.pstyleFoot` `#EBEBEB`)؛ الشريحة المفعّلة والزرّ الذهبيّان يبقيان. البطاقات لم تُمسّ — تسمياتها فوق تدرّج داكن على الصورة فتقرأ في الوضعين.
- **الاختبار:** لقطتان (فاتح: خلفيّة بيضاء ونصّ داكن وشرائح مقروءة / داكن: كما كان) و`npm run ci` يمرّ. رفع `partials-core.js?v=642` و`modules.css?v=656`. الدرس: لا تثبّت لون صفحة يريدها المالك متبعةً للثيم؛ اقلب الحاوية بمتغيّرات الثيم وغطِّ الألوان الثابتة في جسمها بقواعد `html[data-mode="light"]`.

## ١٥ سبتمبر ٢٠٢٦ — v-owner-raw: «قلتلي كلهم خام والحين تقول ثاني — هذا الكذب»
- **العرض:** المالك شعر بتناقض: سابقًا فُهِم أنّ المزوّدين «خام»، وتدقيق لاحق أثبت أنّهم **ليسوا خامًا افتراضيًّا**. الحقيقة الدقيقة: الاتصال بـAPI **أصليّ فعلًا**، لكنّ الوضع الافتراضيّ `balanced` في `api/ai.js` يحقن فوق كلّ سؤال ≈٢٤٤٨ حرفًا من تعليمات التطبيق (تاريخ · دولة · لهجة/نبرة `tone.js` · نيّة `router.js` · `collective` · هويّة)، فالجواب مو ردّ المزوّد الخام. أي: **API خام، الجواب مو خام**. المالك اختار «(ب) خام لك وحدك» بعد عرض التنبيهات (خام للجميع يكسر قواعده الثابتة: قد يكشف الموديل اسم مزوّده أو يدّعي إنسانيّة أو يعطي تاريخًا غلط).
- **القرار:** `api/ai.js` — المالك يأخذ `factory` (خام) افتراضيًّا، والمستخدم يبقى على الافتراضيّ العامّ (`balanced`) المحميّ بقواعده. (أ) استيراد `isOwner` من `_owner.js`. (ب) عند نقطة الحقن يُحسب `b.__ownerFactory = isOwner({query, body})` من التوكن الموقَّع في الجسم، يُستهلك داخل `injectNote` ثمّ **يُحذف** فلا يُمرَّر للمزوّد. (ج) `resolveMode`: طلبٌ صريح (`body.mode`) يتقدّم على الكلّ؛ وإلّا المالك → `factory`؛ وإلّا العامّ. لم تُمسّ قواعد المستخدم ولا الأبواب المقفلة (النقاط/المال) ولا خلل openai premium (بند منفصل بانتظار الإذن).
- **الاختبار:** `tests/owner-raw.test.cjs` (مسجَّل): `resolveMode` (مستخدم=balanced، مالك=factory، الطلب الصريح يتقدّم)، والأثر الفعليّ — `injectNote` يحقن رسالة نظام للمستخدم ولا يحقن شيئًا للمالك (mistral وclaude). `npm run ci` يمرّ، وإثبات بالأرقام على نفس السؤال: المستخدم ٢٤٤٨ حرفًا مُضافة، المالك صفر. الدرس: فرّق بين «API أصليّ» و«جواب خام» — الأوّل بنية، والثاني سلوك؛ والكلمة الواحدة «خام» بلا هذا التفريق تُقرأ كذبًا.

## ١٥ سبتمبر ٢٠٢٦ — v-attach-anyfile + v-attach-picker: «عند + مااقدر احمل صور»
- **العرض:** المالك سجّل فيديو (أندرويد/شاومي): يفتح «+» ← «إرفاق» ← تفتح المعرض ← يختار صورة طفل ← «تم» ← يرجع، **وشريط المرفقات يظلّ فاضيًا**. قال «على كلّ الأجهزة مش الآيفون بس». إعادة الإنتاج: مسار الابتلاع نفسه (change → `omranIngestFiles` → `renderAttachStrip`) يعمل تمامًا على محاكي الجوّال (لقطة: مصغّرة الصورة تظهر داخل الصندوق)، فالعلّة **قبل** الكود: عارضة أندرويد/MIUI تفتح المنتقي وتُرجع الصورة لكن لا تملأ `input.files` ولا تُطلق `change` — والمشتبه: قيمة `accept` على `#attachInput` كانت `image/*,.txt,…,.env,*` (خليط MIME + امتدادات + رمز `*` غير صالح)، وهو نمط معروف يكسر إرجاع الملفّ في MIUI. لا يمكن إعادة إنتاج المنتقي الأصليّ في المحاكي.
- **القرار:** أصغر إصلاح متين على جبهتين مكمّلتين: (أ) **v-attach-anyfile** — إزالة `accept` من `#attachInput` كلّيًّا (يبقى `multiple`)؛ الحقل متعدّد الأغراض (صور · PDF · كود `.js/.env` بلا MIME قياسيّ · مضغوط)، فالتقييد بأنواع يكسر إرفاق الكود، وبلا `accept` يقبل الكلّ والتحقّق يبقى في `omranIngestFiles`. الحقول الأخرى (`imgToPdfInput`/`snapInput` بـ`image/*`) لم تُمسّ. (ب) **v-attach-picker** في `js/app-09-attach.js` — شبكة أمان: عند الضغط على «إرفاق» يُصفَّر علم `__attachHandled` ويُربط مستمع `focus` لمرّة؛ عند عودة التركيز بعد إغلاق المنتقي، إن لم يصل `change` خلال ٥٠٠م.ث نلتقط `input.files` يدويًّا (`__omranTakeAttachFiles`). معالج `change` يحترم العلم فلا يُرفق الملفّ مرّتين.
- **الاختبار:** `tests/attach-picker.test.cjs` (مسجَّل في `package.json`): `#attachInput` بلا `accept` ويبقى `multiple`، والعلم والمستمع والالتقاط اليدويّ وحارس التكرار موجودة. `npm run ci` يمرّ، ولقطة جوّال تثبت أنّ الابتلاع يعرض المصغّرة. الدرس: حين يعمل الكود في المحاكي والعطل عند المستخدم فقط، فالعلّة في الجسر بين المنتقي الأصليّ و`input.files` (accept/عارضة) لا في منطقك — أصلح الجسر ولا تلاحق ما لا تراه. متروك للمالك أن يؤكّد على جهازه (تعذّرت محاكاة منتقي MIUI).

## ١٥ سبتمبر ٢٠٢٦ — v-image-order: «رجّع ترتيب + نفس ما كان قبل، ما قلتلك غيّر الأماكن»
- **العرض:** بعد v-image-modes صارت أوضاع المالك (نصّ دقيق · 4K · نانو · GPT) تُدرَج بين عناصر «+» الأصليّة (`order:41‑44`) فتُزحزح ترتيبها. المالك أراد الترتيب الأصليّ كما كان تمامًا مع بقاء الأوضاع في «+».
- **القرار:** `css/redesign.css` — نقل الأوضاع الأربعة إلى `order:80‑83` لتُلحَق أسفل «حذف المحادثة» (`order:70`) فلا تمسّ مواضع العناصر الأصليّة (إرفاق ٢٠ · PDF ٣٠ · إنشاء صورة ٤٠ · حذف المحادثة ٧٠). رفع `css/redesign.css?v=662`.
- **الاختبار:** لقطة جوّال — الترتيب من الأعلى: إرفاق، PDF، إنشاء صورة، حذف المحادثة، ثمّ الأوضاع الأربعة. `npm run ci` يمرّ. الدرس: عند إضافة عناصر مالك لقائمة قائمة، ألحقها بأطرافها (order أعلى من الكلّ) لا بين عناصرها.

## ١٥ سبتمبر ٢٠٢٦ — v-image-modes: «نانو/GPT في +، ولي أنا وحدي»
- **العرض:** المالك أراد وضع محرّكات الصور في قائمة «+»، وسأل: خام بأسمائها أم فكرة أفضل؟ التوصية: لا أسماء مزوّدين للمستخدم (قاعدة ثابتة) ولا فقدان خطّ الإنقاذ — خيارات بالوظيفة لا بالاسم. اختار «الاثنين، ولي أنا وحدي» فبدأنا **للمالك وحده** (بلا أثر على المستخدم ولا خصم ولا التزام ١٤ لغة الآن).
- **القرار:** أربعة أوضاع «+» للمالك وحده (`owner:true`) للتوليد الجديد: **صورة بنصّ دقيق** (`image_text` → مسار GPT الوفيّ)، **صورة 4K** (`image_hd` → جودة أعلى؛ المالك غير مخصوم فلا مسّ للنقاط)، **محرّك نانو خام** (`image_nano` → يفرض `gemini-2.5-flash-image`)، **محرّك GPT خام** (`image_gpt` → gpt-image مباشرة متجاوزًا Gemini). (أ) `js/modes.js`. (ب) `js/app-09-attach.js`: المرسِل يمرّر أعلامًا (`want4K`/`textFaithful`/`forceEngine`)، والموجِّه يطابق `image*`. (ج) `api/_lib/maha-image.js`: يقرأ الأعلام **للمالك وحده** (`__isOwnerReq`). غير المالك لا يتغيّر عنده شيء.
- **الاختبار:** `tests/image-intent.test.cjs` حُدّث لاستخراج regex الـ4K مع البادئة، `npm run ci` يمرّ، ولقطة: «+» تعرض للمالك image_text/image_hd/image_nano/image_gpt. **التالي (بطلب):** فتح «نصّ دقيق»/«إبداعيّة» للجميع بترجمة ١٤ لغة؛ 4K يبقى منبَّهًا للتكلفة. الدرس: اعرض القدرة لا اسم المزوّد؛ والخيار الخام للمالك = بوّابة خادم لا إخفاء واجهة فقط.

## ١٥ سبتمبر ٢٠٢٦ — v-attach-full: «أيّ ملفّ أرسله داخل التطبيق يتقطّع»
- **العرض:** المالك أرفق ملفًّا في شات التطبيق (نفس الملفّ الكامل ٦٧ ك.ب / ٨٢٩ سطرًا الذي أرسله لـClaude Code سليمًا)، فردّ المساعد «وصل الجزء الأول… يتوقف عند تعليق `restyle` — أرسل التكملة». أي: يصل للنموذج ≈ ١٣ ك.ب فقط. الفحص: العميل يرسل الملفّ كاملًا (apiText حتّى ٢٠٠ ألف حرف، وقراءة الملفّ حتّى ٤٥٠ ألف)، لكن **الخادم** يقصّه: `api/_lib/chat.js` كان يقصّ **كلّ رسالة إلى ١٢ ألف حرف** قبل إرسالها للنموذج (١٢ ألف حرف من ملفّ فيه تعليقات عربيّة ثنائيّة البايت ≈ ١٣٫٦ ك.ب = نقطة `restyle` بالضبط، سطر ١٨٢)؛ ومسار Claude Code `api/_lib/cc.js` يقصّ الرسالة إلى ٢٠ ألف. أمّا وضع الوكيل فيبني التاريخ من `m.content` (النصّ المكتوب) لا من `apiText`، فلا يصل الملفّ إليه أصلًا (خلل أعمق، مؤجَّل).
- **القرار:** الدور الأخير — حامل المرفق — يأخذ سقفًا واسعًا. (أ) `api/_lib/chat.js`: الرسالة الأخيرة `slice(0, 200000)` (نفس حدّ العميل) والتاريخ الأقدم يبقى `12000` لحماية جودة السياق. (ب) `api/_lib/cc.js`: سقف رسالة الشات رُفع من `20000` إلى `200000`. لم يُمسّ وضع الوكيل (يحتاج تخزين `apiText` على الرسالة — تغيير أكبر، بطلب).
