## ١) الفخّ الذي كُشف قبل الوقوع فيه

خطة الإنعاش تأمر ببناء `app.bundle.js` من الأجزاء الأربعة عشر. قِستُ قبل التنفيذ لا بعده:

> **الأجزاء كانت متأخّرة ١٢٢ سطرًا / ٩٢٣٩ حرفًا عن الحزمة الحيّة.**

السبب: رقع **v422** (المسار البصري) و**v423** (أداة النشر) و**v424** (بديل i18n) طُبّقت على الحزمة مباشرةً ولم تُعَد إلى الأجزاء.

**تنفيذ الخطة كما هي كان سيمحو ثلاثة أيام عمل بصمت** — بناءٌ «ناجح» يعيد الموقع إلى ما قبل v422 دون أن يشتكي أحد.

فعكستُ الترتيب: **مزامنة أوّلًا، ثم البوّابة.**

---

## ٢) المزامنة — الأجزاء شرائح، لا ملفّات

`resync-parts.py` يقتطع الأجزاء **آليًّا** من الحزمة الحيّة، والبرهان مدفونٌ في السكربت نفسه:

```
''.join(parts) == app.bundle.js      # حرفًا بحرف
```

لذلك `build.mjs` يستخدم `join('')` لا `join('\n')` — الأجزاء **متلاصقة**، لا مستقلّة.

**قبل الكتابة** تحقّقتُ من مرساتي الحدود لكل جزء:
- التكرار في الحزمة = **١** لكلّ مرساة (فريدة، لا تخمين)
- تشابه الشريحة الجديدة بالقديمة **≥ ٠٫٩٨١**

**md5 الحزمة لم يتغيّر:** `ffb081f2b786` قبل وبعد.

## ٣) صمّام الأمان — لئلّا يتكرّر الفخّ بيد أحد

`scripts/build.mjs` يرفض البناء إذا:

| الشرط | التصرّف |
|---|---|
| فرق أكثر من **٥٠٠ سطر** بين القديم والجديد | رفض، إلّا مع `--force` |
| **نقص** عدد الأجزاء عن المتوقّع | رفض دائمًا |

**جُرِّب على نسخة معزولة `/tmp/gt` قبل النشر:**
- إفراغ جزء (−٢٧٦٥ سطرًا) ← **رُفض**
- الأمر نفسه مع `--force` ← **قُبل**
- حذف جزء ← **رُفض**

## ٤) لماذا `bundle` لا `build`

فحصتُ إعداد المشروع على Vercel: **بلا إطار (`framework: null`) وبلا `buildCommand`**.

وجود سكربت اسمه `build` في `package.json` يدفع Vercel لتشغيله **تلقائيًّا على كل نشر**، ويغيّر استنتاج مجلّد المُخرَج — أي احتمال أن يُخدَم مجلّدٌ فارغ.

**لا أقامر بموقعٍ حيّ مقابل اسم.** السكربت: `npm run bundle`.

## ٧) بندان في الخطة كانا مبنيَّين على ظنّ

**① `sw.js` ليس سبب «الأخطاء التي لا تتكرّر».**
قرأتُه سطرًا سطرًا: القشرة والـJS **شبكة-أوّلًا** (سطر ١٢٨)، و`activate` يحذف الكاشات القديمة (سطر ٦٧). **لا أحد مُجمَّد على نسخة قديمة.** البصمة نُفِّذت للنظافة وحسم الالتباس، لا كعلاج نزيف.

**② `.vercelignore` منجَزٌ منذ قبل.** البند كان يطلب إنشاءه؛ كان قائمًا ويعمل.

## ٨) التحقّق

**محليًّا**
- `md5` الحزمة قبل البناء = بعده
- `node --check` أخضر لكل ملفّ js

**حيًّا على الإنتاج**
- البصمة `18c2ed1c` في `index.html` و`sw.js` — الموضعان متطابقان
- الحزمة المخدومة `ffb081f2b786` = المحلّية **بايتًا**
- **١٨/١٨** جزءًا محجوب (404) · `scripts/build.mjs` محجوب
- `i18n/ur.js` · `templates-data.js` · `manifest.json` ما زالت **200**

**البرهان الكامل — من المستودع وحده**
```
git clone --depth 1 main  →  npm run bundle
  ⇒ الحزمة الناتجة مطابقة للحزمة الحيّة بايتًا
  ⇒ npm run verify  أخضر
  ⇒ npm run check   أخضر
```

**المستودع صار مصدر حقيقة قابلًا للبناء — وهذا ما لم يكن موجودًا قطّ.**
